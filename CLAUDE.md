# HANDOFF: Telegram-бот сповіщень про відкриття черги ДП «Документ»

> Документ для передачі проєкту в Claude Code. Стан на 03.11.2026.

---

## 1. Поточний стан проєкту

### Що вже реалізовано
- Telegram-бот на **aiogram 3** (long polling), який:
  - дає користувачу підписатися на пару «місто + послуга» через inline-кнопки;
  - у фоні раз на `CHECK_INTERVAL` секунд (за замовчуванням 180 с + випадкові 0–30 с) перевіряє **вільні дати** в черзі;
  - надсилає **одне повідомлення на місто+послугу** з переліком нових дат (час талона свідомо не відстежується — потрібні лише дата й факт відкриття черги);
  - не дублює сповіщення про ту саму дату (таблиця `seen`, записи старші 3 днів чистяться);
  - при 401/403 від сайту один раз пише адміну, що сесія (Cookie) закінчилась;
  - при помилках мережі робить експоненційний backoff (до ×8 від інтервалу).
- **Демо-режим** (`MODE=demo`): генерує випадкові «відкриті дати», щоб протестувати бота без реального джерела.
- **Live-режим** (`MODE=live`): GET-запит на `SLOTS_URL` з Cookie / Authorization, далі `parse_response()`.

### Що НЕ реалізовано (головне)
- **Реальне джерело даних невідоме.** `SLOTS_URL` порожній, `parse_response()` — заглушка під вигаданий формат `{"items":[...]}`. Публічного API в ДП «Документ» немає; ендпоінт треба знайти через DevTools → Network на сайті запису.

### Основні файли
| Файл | Призначення |
|---|---|
| `bot.py` | Точка входу: хендлери команд/кнопок, фоновий цикл `checker()`, `main()` |
| `fetcher.py` | Отримання даних: демо-генератор, live-запит, `parse_response()`, виняток `SessionExpired` |
| `db.py` | SQLite через aiosqlite: підписки та «вже бачені» дати |
| `config.py` | Читання `.env`, списки міст і послуг |
| `requirements.txt` | Залежності |
| `.env.example` | Шаблон змінних середовища |
| `README.md` | Інструкція для користувача (укр.) |

## 5. Проблеми та недоробки

### Баги (підтверджені)
1. **`ADMIN_ID=your_telegram_id` з шаблону валить запуск**: `ValueError: invalid literal for int()` у `config.py`. Треба безпечний парсинг (не число → 0 + warning) або порожнє значення в `.env.example`.
2. **Порожній `BOT_TOKEN` падає з `TokenValidationError` ще при імпорті** (`bot = Bot(config.BOT_TOKEN)` на рівні модуля), тож перевірка з дружнім повідомленням у `main()` не спрацьовує. Перенести створення `Bot` у `main()`.
3. **Дата позначається «баченою», навіть якщо підписників немає.** Хто підпишеться пізніше, не дізнається про вже відкриті дати.

### Логічні невідповідності
4. **Немає сповіщення про закриття черги** і немає «поточного стану». Якщо дата зникла й знову з'явилась протягом 3 днів — повторного сповіщення не буде.
5. **При `SessionExpired` немає backoff** — бот і далі б'є в сайт з 401 кожні ~3 хв.
6. **Після оновлення Cookie потрібен перезапуск.**
7. **`callback_data` використовує індекси списків.** Якщо змінити порядок `CITIES`/`SERVICES`, старі кнопки ведуть не туди.
8. **Назви міст/послуг мусять точно збігатися з тим, що повертає сайт**, інакше підписники не знайдуться.

### Недоробки
9. Користувачі, що заблокували бота, не видаляються з `subs`.
10. Немає обробки `TelegramRetryAfter` (429).
11. Немає відписки від однієї підписки (лише `/stop`); немає `/status` (поточні відкриті дати).
12. Немає `.gitignore`, тестів, Dockerfile.
